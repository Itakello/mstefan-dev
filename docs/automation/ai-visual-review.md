# Automatic AI visual review

The trusted default-branch `AI visual review` workflow consumes a successful `Visual review` run. It checks its repository, workflow, immutable workflow head, current PR head/base and artifact metadata, reads named current PNGs as inert data, and compares all 16 Home/Work/About/footer captures and every supplied Workshop matrix with base `DESIGN.md`, `AGENTS.md`, `.github/PR_POLICY.md`, and approved Linux baselines (all 16 page references are mandatory). The producer records every story ID from `.artifacts/workshop/index.json`; every story must have all four viewport/theme captures, including future additions. Base `.storybook/main.ts` makes Workshop evidence mandatory for every UI review. The raw PR diff must contain exactly the authoritative PR file inventory; quoted/unsupported paths fail closed rather than being parsed permissively. Initial Workshop references may be absent; related page evidence remains mandatory. Proven findings block the exact-head `AI visual review` status; subjective suggestions do not. No PR code runs with credentials, no comments or baseline updates are published.

Automatic review starts disabled. Before setting repository variable `MSTEFAN_AI_VISUAL_REVIEW_ENABLED=true`, verify spending authorization and run attended acceptance after this workflow is on the default branch, using the existing `OPENAI_API_KEY` repository secret. Add `AI visual review` to required statuses only after that proof. The variable pauses automatic requests: a disabled `workflow_run` UI review with verified current artifact metadata reports error without calling the model. Explicit owner `workflow_dispatch` runs remain available for attended acceptance under approved spending, even while the variable is false; all source checks, replay claims and budgets still apply. Native review quota and this API budget are separate.

After budget approval, dispatch on the default branch with a completed exact-head source run while automatic review remains paused:

```sh
gh workflow run ai-visual-review.yml --ref master -f source_run_id=RUN_ID
```

The request uses `gpt-6.1-sol`, medium reasoning, standard service tier, `store=false`, and no tools. Trusted preparation counts exact input tokens before recording a reservation; the paid step recounts and rejects any increase above that bound. Exact input-token preflight uses the [Responses counter](https://developers.openai.com/api/docs/guides/token-counting). A maximum 12,000 output tokens and conservative long-context prices including cache writes ($5/M input, $15/M output, [pricing checked 2026-10-11](https://developers.openai.com/api/docs/pricing)) enforce the approved $2 upper bound per review. Recheck prices before activation. One generation request, no retries; independently cap 20 paid reservations and $10 total reserved generation cost in a rolling 24 hours. Each reservation uses integer microUSD: input tokens × 5 plus 12,000 output tokens × 15, at most 2,000,000 microUSD per review. Failed, cancelled and in-flight paid steps retain their full bound; this is a conservative reservation ledger, not measured actual spend. Docs-only, paused, stale and invalid-evidence runs do not reserve paid attempts. The trusted preparation step gates a paid step whose immutable Actions name records its validated microUSD amount; Actions job/step records are the reservation history. The window includes a conservative 10-minute overlap for the job's maximum request delay. The guard lists the last 36 days of runs to cover GitHub's [35-day workflow lifetime including queueing](https://docs.github.com/en/actions/reference/limits), requires complete listings (at most 1,000 runs and fewer than 100 jobs per run), and fails closed on API gaps or an invisible current reservation. The 37 pre-upgrade paused runs verified through attended logs remain excluded by exact run ID. Two additional exact historical steps are excluded after logs proved generation was never reached: the expected legacy review step in [run 38100300733](https://github.com/Itakello/mstefan-dev/actions/runs/38100300733) stopped at the activation gate, and the fixed-name paid step in [run 38100604189](https://github.com/Itakello/mstefan-dev/actions/runs/38100604189) failed its input-token count with HTTP 401 before generation. Only those exact run-ID/step-name pairs are free; other legacy review steps and every other fixed-name paid step reserve $2 because actual cost is unknown. These zero-generation exemptions rest on Actions logs showing the generation call was never reached; rounded billing UI totals and billing adjustments are not proof of zero charges. No prior spend is reset or dropped. Global concurrency serializes claims; a head/base status claim prevents replay, including errors after the request claim. Disabled validation does not claim a request and can be dispatched again after approval. A fresh head or base is necessary for another attempt. This trades recovery convenience for bounded spending. Input limits: 100 current captures, 200 total images, 5 MiB/image, 60 MiB PNG bytes, 500 KiB text, 250 MiB archive expansion. Missing evidence, truncated API listings/output, quota, timeout, refusals, malformed coverage and revision changes fail closed. The Actions summary preserves rejected model message output as explicitly unvalidated, fenced JSON; it excludes request inputs and reasoning. Read that report to diagnose incomplete coverage or refusals; it never establishes approval.

Source events include edits/retargets, labels and synchronization. The consumer independently classifies exact changed paths; the owning review workflows and tests are conservative UI triggers. Documentation-only changes skip the model and publish success with that reason. Artifact content and model output remain untrusted; complete named coverage is necessary evidence, not a guarantee that AI detects every visual defect. Verify both a known violation and clean evidence, disabled state, budget cap, replay and stale revision in attended acceptance before enabling.

The separate trusted `AI visual review pending` workflow handles PR open, synchronization, reopen and edits through `pull_request_target`, checking out only the default branch without PR installs or execution. It fetches the literal current PR head/base and immediately publishes pending if that tuple differs from the latest AI status; edits on the same tuple preserve its current claim or final result. Its concurrency is separate from paid review so retarget invalidation does not wait behind model requests. Failed/cancelled producers leave the current pending status intact because their associated PR metadata can change and cannot prove the original base. UI review statuses require the immutable workflow head and artifact head/base metadata; stale or untrusted UI producer runs write no current-head status. Documentation-only success derives independently from the current authoritative file inventory and a fresh live revision check. Invalidation uses no OpenAI credential and does not activate automatic model requests.
