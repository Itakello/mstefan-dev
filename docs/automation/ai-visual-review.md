# Automatic AI visual review

The trusted default-branch `AI visual review` workflow consumes a successful `Visual review` run. It checks its repository, workflow, immutable workflow head, current PR head/base and artifact metadata, reads named current PNGs as inert data, and compares all 16 Home/Work/About/footer captures and every supplied Workshop matrix with base `DESIGN.md`, `AGENTS.md`, `.github/PR_POLICY.md`, and approved Linux baselines (all 16 page references are mandatory). The producer records every story ID from `.artifacts/workshop/index.json`; every story must have all four viewport/theme captures, including future additions. Base `.storybook/main.ts` makes Workshop evidence mandatory for every UI review. The raw PR diff must contain exactly the authoritative PR file inventory; quoted/unsupported paths fail closed rather than being parsed permissively. Initial Workshop references may be absent; related page evidence remains mandatory. Proven findings block the exact-head `AI visual review` status; subjective suggestions do not. No PR code runs with credentials, no comments or baseline updates are published.

Automatic review starts disabled. Before setting repository variable `MSTEFAN_AI_VISUAL_REVIEW_ENABLED=true`, verify spending authorization and run attended acceptance after this workflow is on the default branch, using the existing `OPENAI_API_KEY` repository secret. Add `AI visual review` to required statuses only after that proof. The variable pauses automatic requests: a disabled `workflow_run` UI review with verified current artifact metadata reports error without calling the model. Explicit owner default-branch `workflow_dispatch` runs remain available for attended acceptance under approved spending, even while the variable is false; all source checks, replay claims and budgets still apply. Native review quota and this API budget are separate.

For ordinary attended acceptance after budget approval, dispatch on the default branch with a completed exact-head source run while automatic review remains paused:

```sh
gh workflow run ai-visual-review.yml --ref master -f source_run_id=RUN_ID
```

The request uses `gpt-6.1-sol`, medium reasoning, standard service tier, `store=false`, and no tools. Exact input-token preflight uses the [Responses counter](https://developers.openai.com/api/docs/guides/token-counting). A maximum 12,000 output tokens and conservative long-context prices including cache writes ($5/M input, $15/M output, [pricing checked 2026-10-11](https://developers.openai.com/api/docs/pricing)) enforce the approved **$2 maximum per review**. The paid step recounts tokens immediately before its single generation request and rejects any increase beyond that bound. There is no rolling daily dollar cap, monetary allowance, historical cost aggregation or settlement-provenance admission check. Returned usage is reported after the review with its response ID, model/tier, token counts and computed actual cost; it does not change attempt admission or establish visual approval.

Independently cap 20 paid attempts in a rolling 24 hours. Count genuine, failed, cancelled and in-flight paid steps from complete Actions job history; receipt availability and reported historical dollar amounts do not change that count. The 37 proven pre-upgrade paused runs and two exact first-attempt zero-generation steps remain excluded. Queued, skipped, docs-only, paused, stale and invalid-evidence runs do not consume paid attempts. History includes a conservative 10-minute overlap and lists 36 days of runs to cover GitHub's [35-day workflow lifetime](https://docs.github.com/en/actions/reference/limits); missing/truncated jobs or an invisible current paid step fail closed. Global concurrency serializes requests, and the exact head/base claim bars replay even after errors. No retries or automatic replenishment of attempts are permitted within the rolling window.

The credential-free reporting step publishes only the validated usage receipt, never request inputs or credentials. Actual usage includes ordinary, cached and cache-write input plus total output, including reasoning, at the [2026-10-12 model rates](https://developers.openai.com/api/docs/models/gpt-6.1-sol). Unsupported models/tiers or inconsistent usage counters fail closed. The Actions summary preserves rejected model output as unvalidated fenced JSON. Input limits remain 100 current captures, 200 total images, 5 MiB/image, 60 MiB PNG bytes, 500 KiB text and 250 MiB archive expansion. Missing evidence, API gaps, timeout, refusals, incomplete coverage and changed revisions fail closed.

Source events include edits/retargets, labels and synchronization. The consumer independently classifies exact changed paths; the owning review workflows and tests are conservative UI triggers. Documentation-only changes skip the model and publish success with that reason. Artifact content and model output remain untrusted; complete named coverage is necessary evidence, not a guarantee that AI detects every visual defect. Verify both a known violation and clean evidence, disabled state, per-review and attempt limits, replay and stale revision in attended acceptance before enabling.

The separate trusted `AI visual review pending` workflow handles PR open, synchronization, reopen and edits through `pull_request_target`, checking out only the default branch without PR installs or execution. It fetches the literal current PR head/base and immediately publishes pending if that tuple differs from the latest AI status; edits on the same tuple preserve its current claim or final result. Its concurrency is separate from paid review so retarget invalidation does not wait behind model requests. Failed/cancelled producers leave the current pending status intact because their associated PR metadata can change and cannot prove the original base. UI review statuses require the immutable workflow head and artifact head/base metadata; stale or untrusted UI producer runs write no current-head status. Documentation-only success derives independently from the current authoritative file inventory and a fresh live revision check. Invalidation uses no OpenAI credential and does not activate automatic model requests.
