# Automatic AI visual review

The trusted default-branch `AI visual review` workflow consumes a successful `Visual review` run. It checks its repository, workflow, current PR head/base and artifact metadata, reads named current PNGs as inert data, and compares all 16 Home/Work/About/footer captures and every supplied Workshop matrix with base `DESIGN.md`, `AGENTS.md`, `.github/PR_POLICY.md`, and approved Linux baselines (all 16 page references are mandatory). The producer records every story ID from `.artifacts/workshop/index.json`; every story must have all four viewport/theme captures, including future additions. Base `.storybook/main.ts` makes Workshop evidence mandatory for every UI review. The raw PR diff must contain exactly the authoritative PR file inventory; quoted/unsupported paths fail closed rather than being parsed permissively. Initial Workshop references may be absent; related page evidence remains mandatory. Proven findings block the exact-head `AI visual review` status; subjective suggestions do not. No PR code runs with credentials, no comments or baseline updates are published.

Automatic review starts disabled. Before setting repository variable `MSTEFAN_AI_VISUAL_REVIEW_ENABLED=true`, verify spending authorization and run attended acceptance after this workflow is on the default branch, using the existing `OPENAI_API_KEY` repository secret. Add `AI visual review` to required statuses only after that proof. The variable pauses automatic requests: a disabled `workflow_run` UI review reports error without calling the model. Explicit owner `workflow_dispatch` runs remain available for attended acceptance under approved spending, even while the variable is false; all source checks, replay claims and budgets still apply. Native review quota and this API budget are separate.

After budget approval, dispatch on the default branch with a completed exact-head source run while automatic review remains paused:

```sh
gh workflow run ai-visual-review.yml --ref master -f source_run_id=RUN_ID
```

The request uses `gpt-6.1-sol`, medium reasoning, standard service tier, `store=false`, and no tools. Exact input-token preflight uses the [Responses counter](https://developers.openai.com/api/docs/guides/token-counting). A maximum 12,000 output tokens and conservative long-context prices including cache writes ($5/M input, $15/M output, [pricing checked 2026-10-11](https://developers.openai.com/api/docs/pricing)) enforce the approved $2 upper bound per review. Recheck prices before activation. One generation request, no retries; cap 5 paid reservations in a rolling 24 hours, conservatively including failed, cancelled and in-flight paid steps (at most $10 in review generation costs per 24 hours at the approved $2 bound). Docs-only, paused, stale and invalid-evidence runs do not reserve paid attempts. The trusted preparation step gates a uniquely named paid step; Actions job/step records are the reservation history. The window includes a conservative 10-minute overlap for the job's maximum request delay. The guard lists the last 36 days of runs to cover GitHub's [35-day workflow lifetime including queueing](https://docs.github.com/en/actions/reference/limits), requires complete listings (at most 1,000 runs and fewer than 100 jobs per run), and fails closed on API gaps or an invisible current reservation. The 29 pre-upgrade paused runs verified through attended logs are excluded by exact run ID; other legacy review steps count conservatively. Global concurrency serializes claims; a head/base status claim prevents replay, including errors after the request claim. Disabled validation does not claim a request and can be dispatched again after approval. A fresh head or base is necessary for another attempt. This trades recovery convenience for bounded spending. Input limits: 100 current captures, 200 total images, 5 MiB/image, 60 MiB PNG bytes, 500 KiB text, 250 MiB archive expansion. Missing evidence, truncated API listings/output, quota, timeout, refusals, malformed coverage and revision changes fail closed.

Source events include edits/retargets, labels and synchronization. The consumer independently classifies exact changed paths; the owning review workflows and tests are conservative UI triggers. Documentation-only changes skip the model and publish success with that reason. Artifact content and model output remain untrusted; complete named coverage is necessary evidence, not a guarantee that AI detects every visual defect. Verify both a known violation and clean evidence, disabled state, budget cap, replay and stale revision in attended acceptance before enabling.

The separate trusted `AI visual review pending` workflow handles PR open, synchronization, reopen and edits through `pull_request_target`, checking out only the default branch without PR installs or execution. It fetches the literal current PR head/base and immediately publishes pending if that tuple differs from the latest AI status; edits on the same tuple preserve its current claim or final result. Its concurrency is separate from paid review so retarget invalidation does not wait behind model requests. A trusted completed producer failure/cancellation for the exact current tuple reports error; stale or untrusted producer runs never write a current-head status. Invalidation uses no OpenAI credential and does not activate automatic model requests.
