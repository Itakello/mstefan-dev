# UI exploration

## CI preview exploration

`Codex UI exploration` continues a successful `PR previews` workflow from protected `master`. It verifies a same-repository open PR, its current base/head, the preview deployment's owner and exact commit, and the latest successful canonical `https://pr-N.preview.mstefan.dev` deployment status. A manual dispatch accepts a PR number with the same checks. The existing trusted UI-path classifier skips changes without UI impact before reserving a model run. The runner never executes PR code: it fetches Git objects for the diff and uses the trusted master runner, browser initialization and base instructions.

A fresh Codex CLI 0.131.0 session runs GPT-6.1 Sol at medium reasoning and chooses scenarios and screenshots from the diff. This runtime is pinned for its verified classic MCP catalog; 0.162.1 did not register the configured browser tools in synthetic acceptance probes. Playwright MCP exposes only the browser tool allowlist. The remote session explicitly approves that restricted server’s tools for unattended execution; Codex’s read-only sandbox and the relay/network guards remain enforced. Without that scoped setting, default MCP approvals can cancel navigation and closure in a non-interactive session even when snapshots succeed; missing navigation must remain an incomplete result. The model relay advertises only those browser functions and validates the complete response before forwarding any tool call, rejecting built-in or unknown calls. Its isolated browser permits GET/HEAD on the exact preview origin, also permits the site’s public Iconify JSON/SVG assets through narrowly validated read-only paths, and blocks other external requests, service workers and WebSockets, and stops tracing before closing. External asset or integration failures are coverage limitations, not automatic website findings. A fresh cache-busting readiness probe rejects cached or unsuccessful responses before admission and each paid model turn; browser preview requests also bypass cache and reject cached responses. Reports, chosen screenshots, browser actions, trace/session and usage receipts are retained as a 14-day workflow artifact. A successful report must contain actual browser and image evidence; findings, missing evidence, model failures and changed PR identity fail the job and publish `Codex UI exploration` status. Both `Codex UI exploration` and `AI visual review` are advisory in this repository; the deterministic `Visual review gate` remains required.

CI uses the existing repository `OPENAI_API_KEY` through a trusted loopback Responses relay. The actual key remains in that parent process; Codex receives a dummy relay key and a fresh account/configuration directory. The relay fixes the model, reasoning and service tier, counts input before each paid request, limits output to 12,000 tokens per turn, and enforces a total $2 ceiling for the session with at most 20 model requests. An uncertain request retains its full reservation and closes the lane. There are no paid retries or model fallbacks. The model session is limited to ten minutes, with a 15-minute workflow limit.

Both this workflow and the legacy paid screenshot reviewer share concurrency and a rolling $10 budget. Exploration sessions reserve $2 conservatively for 24 hours plus the outer 15-minute limit, including failed runs. Replay of the same PR head/base is rejected after a claim; changed code creates a new review identity. A maximum of five exploration reservations can fit the daily cap before any legacy-review spending. The first seven-day pilot therefore permits at most 35 sessions and $70 combined spend; actual use depends on successful preview deployments and UI work. Its owner is the repository owner, and its success measure is a complete retained browser session for an exact-head preview, with useful reproducible findings or explicit coverage gaps.

Automatic activation requires `MSTEFAN_CODEX_UI_EXPLORATION_ENABLED=true` and `MSTEFAN_CODEX_UI_EXPLORATION_EXPIRES_AT` set to an ISO timestamp no more than seven days ahead. Expired or missing activation fails closed, including before every generation. A repository-owner manual dispatch can run the approved acceptance session while automatic activation remains false; the same expiry, source, replay and budget checks apply. For example, after cost approval and preview recovery, set a bounded expiry and run `gh workflow run codex-ui-exploration.yml --ref master -f pr_number=<number>`. Keep automatic activation false until that complete live session is verified. Set the enabled variable to `false` to pause new automatic runs; already admitted sessions retain their runtime and expiry limits. Do not cancel an in-flight paid request to retry it. Delete neither usage history nor claim statuses to bypass the budget/replay guard. Review the pilot before extending its expiry. A GitHub rerun is not a recovery route; resolve the failure and use a new code revision or an explicitly reviewed contract change.

Hosted previews must separately be healthy and enabled. This integration does not resume the paused deployment controller or clear its infrastructure acceptance requirements. Deployment, replay and cleanup proof and approval for the new recurring API spending precede enablement. The synthetic CLI probe verifies the requested model reaches the isolated Responses provider without ChatGPT authentication, but it does not prove a paid end-to-end browser run.

## Attended fixture exploration

`pnpm test:explore-ui --base-ref <commit> --output-dir .artifacts/review-<name>` builds an exact-head isolated production fixture, prepares the review packet and keeps its server alive for an attended desktop Codex review for at most ten minutes. Use a clean candidate worktree without `.env` files. The fixture owner reads `fixture.json` and sends `prompt.txt` to a fresh independent Codex `gpt-6.1-sol` session at medium reasoning. That session chooses what to explore using the generated browser configuration, captures evidence and closes its browser before reporting. Stop the fixture owner with SIGINT after the review; it shuts down the server and removes the disposable database. `--reuse-build` accepts only a stamped build for the exact checked-out head.

For the desktop route, use the official Playwright CLI pinned at `0.1.22` with one fresh named session and `open --config <output>/browser-config.json`. Set only `PLAYWRIGHT_BASE_URL` and `VISUAL_NOTION_FIXTURE_STATE` from `fixture.json` for the browser subprocess. The review packet's schema defines `report.json`; save the actual command history too. A desktop session retains its own tool permissions: this attended route does not inherit the CI relay's browser-only enforcement. Keep its actions scoped to the fixture and verify findings independently. This is not an unattended runner or a CI approval.


Unlike the screenshot comparison, the reviewer chooses interaction scenarios from the exact diff and approved design contract. It receives base-branch `AGENTS.md`, `DESIGN.md`, and PR policy, then explores with the official Playwright browser tools. The standalone CLI adapter uses pinned Playwright MCP 0.0.83; the attended desktop route uses Playwright CLI 0.1.22. Snapshot inspection and returned screenshot images support functional and visual observations. Findings include reproduction, affected location, contract, and evidence. An independent human or agent should reproduce consequential findings before changing code.

The browser has an isolated profile, blocked service workers and WebSockets, and the base-approved offline fixture HTTP routes. Exploration builds and servers receive an allowlisted environment and reject local production env files. These routes provide offline fixture behavior, not a security sandbox for arbitrary hostile candidate code. In the standalone CLI lane, the reviewer runs in a generated packet outside the candidate repository, ignores user configuration, retains enforced rules and approvals, and has a browser-only MCP tool allowlist. The configured MCP catalog excludes arbitrary browser code, evaluation and uploads. This standalone configuration does not prove that all built-in Codex tools are absent; the CI relay separately filters the model catalog and validates every returned tool call before forwarding it. The MCP process receives only local fixture paths and the reviewer uses existing Codex account authentication; no API keys are transferred. This is attended review, not a provider-write workflow or CI gate.

The standalone CLI lane saves evidence under its selected directory (default `.artifacts/exploring-ui-review`): exact packet, invocation and refs, JSONL events, stderr, structured `report.json`, validated `result.json`, browser screenshots, MCP session, and Playwright trace. The ten-minute limit produces an incomplete result. Missing navigation, snapshot inspection, retained screenshots, observed scenarios, finalized trace/session, wrong refs, or reported coverage gaps also fail closed; an empty findings list alone is never a clean result. Use `tracing-start` before exploring and `tracing-stop` before `close` in Playwright CLI (or the corresponding MCP tracing tools). A stopped trace consists of its `.trace`, `.network`, and resource files; closing alone does not establish finalized tracing. The fixture does not prove live Notion, account, or external integration behavior.

`--prepare-only` assembles the pinned packet, `prompt.txt`, and `browser-config.json` without launching Codex. This is preparation, never a completed review. It supports an attended reviewer in an already authorized desktop session while the fixture owner keeps the local server alive. To attempt the standalone CLI lane, run `node scripts/visual-review/run-fixture.mjs --explore --base-ref <commit> --output-dir <empty-directory>`. The standalone CLI lane requires account support for the exact model: the local CLI currently rejects `gpt-6.1-sol` with ChatGPT authentication, so it produces an incomplete result and must not silently switch models or API billing. A desktop or Playwright CLI route must verify its own actual tools and evidence; the standalone CLI tool restrictions do not automatically carry over.
